## 板块 A：技术向 / B2B / 基础设施 AI

### 今天最值得关注的 A 类产品

**1. HarnessRouter Community Edition —— 用一套开放协议统一 Codex / Claude Code 等 agent harness，可自托管（评分 15/18）**

- **定位**：Epsilla（YC S23）推出的开源（Apache-2.0）自托管版 agent harness 网关，官网 harnessrouter.ai/open-source，仓库 github.com/HarnessRouter/harnessrouter。是 07-25 曾覆盖的托管版 HarnessRouter 的开源社区版本。
- **真实问题**：现在每种 coding/agent harness（Codex、Claude Code、Hermes……）都有各自的会话、流式、取消、重试、产物、权限语义，团队把它们当"产品后端"接入时要为每一种重写胶水层，且托管方案要把代码和密钥交出去。
- **核心机制**：把 Gateway + Runner + Console 打包进一个 Docker 容器，对外暴露一套 **OpenAI Responses 兼容 API**，统一处理会话 / 流式 / 取消 / 幂等 / 文件产物 / 失败恢复；底层用**开放且带版本的 Unified Harness Protocol（UHP）**描述各 harness，因此可以「配置切换 harness、上层接口不变」。全程跑在自己基础设施上、用自己的密钥、本地 SQLite + 工作区卷、无遥测；托管版 HarnessRouter Cloud 走同一套 UHP API。
- **为何现在关注**：08-16 已看到 DeepSeek Harness（Cordis 插件内核，"一切皆插件"）、Munder Difflin（把多个 CLI 编排成自协调克隆团队）在做 harness 抽象；HarnessRouter 把这件事进一步抬到「开放协议 + 一致 API + 可自托管」层面，指向 harness 互操作正在标准化。
- **失败风险**：UHP 若不能被主流 harness 采纳，就退化成又一个"只接了几家"的适配层；harness 因授权原因需首次运行时自行安装，也增加落地摩擦；且"统一接口"本质上是 LiteLLM 式聚合，护城河取决于协议能否成为事实标准而非厂商各自为政。
- **对混元 API / Agent 启发**：如果要把混元做成能被外部当"agent 后端"调用的平台，值得借鉴其把**会话 / 流式 / 取消 / 幂等 / 产物 / 失败恢复**收敛为一层稳定契约，并用带版本的协议描述可替换的执行体——这比单纯暴露一个 chat 接口更接近"agent 平台"形态。
- **评分**：相关 5 / 机制新颖 4 / 启发 4 / 信号 2 = 15/18。链接：https://harnessrouter.ai/open-source

### A 类趋势信号

1. **agent harness / 编排层正在标准化并走向可插拔、可自托管。** 跨天看：DeepSeek Harness（插件内核）、Munder Difflin（多 CLI 克隆编排，08-16）到今天 HarnessRouter CE（UHP 开放协议 + OpenAI Responses 兼容 + 自托管），三者都在把"如何驱动一个 coding agent"从各自私有实现收敛成可替换、可迁移的统一层。这是本周期 A 端最清晰的结构性信号——harness 正从"工具"变成"有协议的基础设施"。其背后的产品逻辑是：一年前大家争的是"模型 API 兼容层"（OpenAI 兼容格式几乎成事实标准），现在竞争前移到了"agent 执行体兼容层"——谁能把会话、产物、审批、失败恢复这些执行语义标准化，谁就更可能成为别人 agent 应用的默认后端。这对任何想做 Agent 平台的厂商都是一个正在打开、但尚未被占据的位置。
2. **agent 的执行 / 沙箱环境开始以 MCP-native 形式向硬件等垂直域延伸**（见附录 Chiplab）：让 coding agent 自己构建、运行、读回结果，而不是人去驱动工具链——尚未成势，先记一笔。

## 我最想跟进的方向

- **技术向**：UHP（Unified Harness Protocol）能否被 Codex / Claude Code 等主流 harness 之外的第三方采纳——若成事实标准，则"agent 后端"会像今天的 OpenAI 兼容 API 一样出现互操作层，对做 Agent 平台的一方是重要窗口。反过来看，harness 抽象层最近一周密集出现（DeepSeek Harness、Munder Difflin、HarnessRouter），也可能意味着大家都在"抢协议定义权"、最终各自为政，值得跟踪的是有没有哪家的接口被别人主动兼容——这才是标准化真正发生的信号，而非各写各的适配器。
- **2C**：本周消费向新品持续稀薄且多为非 AI 或套壳，值得盯的是"生成式创作工作站"（Suno Studio 类）之外，是否出现真正 AI 为核心、有留存假设的个人助理/学习/健康新品，而非又一个健康评分或闹钟；同时留意 Expeditione 这类非 AI 但体验精良的内容产品——若后续接入生成式能力做"可对话/可生成的交互百科"，才可能进入本雷达视野。
